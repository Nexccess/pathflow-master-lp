# Path-Flow Lite 大量生産パイプライン

## 商売上の目的

最初の921件をゴールにしない。第1市場としてLP販売率0.5〜0.8%（約5〜7件）を検証し、成功したら地域・業種を差し替えて同じ製造ラインを再利用する。

## 製造ライン

1. **SOURCE** — Google Maps等の公開情報・口コミを取得
2. **FACT NORMALIZE** — 店名、住所、営業時間、評価、メニュー等を事実データとして正規化
3. **STORE UNDERSTANDING** — AIが口コミの反復傾向、訴求可能事項、非訴求事項を整理
4. **EXPERIENCE GENERATION** — LPコピー、特徴、利用フロー、受付質問を生成
5. **VALIDATION** — 別工程で未確認表現、禁止内容、メニュー不整合等を検査
6. **PUBLISH DATA** — 合格した店舗だけ `store-profiles.json` 相当の公開データへ追加
7. **SHARED TEMPLATE** — 共通テンプレートが店舗IDでデータを読み分ける
8. **OUTREACH** — 店舗専用URLをDMへ使用
9. **HUMAN ENTRY** — 反響があった店舗から人間が写真・コピー等を仕上げる

## AIの役割分離

### 製造AI（ローカル候補: Ollama/Qwen）
大量処理。店舗理解、コピー、質問、構造化JSON生成を担当。API費用を抑え、地域・業種展開時にも再利用する。

### 受付AI（Vercel/Gemini）
エンドユーザーがページ上で回答した瞬間だけ使用。聞く→整理→穏やかな提案を担当する。

### 検品工程
制作AIの自己評価だけに依存しない。決定論的チェックを先に通し、必要に応じて別AI検品を追加する。人間は原則としてFAIL/WARNだけを見る。

## 業種パック

共通エンジンへ業種知識を直接焼き込まない。`data/industry-packs/` に業種別の質問観点・禁止事項・受付ヒントを置く。

- 新地域 = 原則、入力データの差し替え
- 新業種 = 原則、業種パックの追加
- 共通エンジン = 原則、変更しない

## 品質ゲート

公開候補は最低限以下を満たすこと。

- 店名・業種等の必須FACTがある
- 受付質問が3〜7問
- 未確認の具体的メニュー・価格を作らない
- 根拠のない品質訴求をしない
- `doNotPromote` の内容をLPへ出さない
- 経営者向けの売上・集客改善診断をEU受付へ混ぜない

## 最初の拡張順

44番でUX確認 → 既存10店舗 → 50店舗 → DM実戦 → 第1市場921件。

50店舗段階から「全件を人間が読む」運用は禁止する。検品で弾かれた例外だけを見る。
